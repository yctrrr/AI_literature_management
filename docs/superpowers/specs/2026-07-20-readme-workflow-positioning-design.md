# README Workflow Positioning Design

## Goal

Reposition AI Literature Management as a local-first research literature and personal knowledge workflow. Keep automated literature collection as one optional capability rather than the project identity.

## Scope

- Rewrite `README.md` and `README.zh.md` around the full workflow: collect, organize, locate, understand, and cite.
- Introduce the five reusable skills as focused capabilities within that workflow.
- Keep installation, local configuration, privacy boundaries, and command entry points.
- Replace root-level crawl tutorials and scheduler detail with concise links to `weekly-literature-crawl` documentation.
- Preserve exact, explicit confirmation boundaries for downloads, Zotero changes, and DOCX edits.

## Structure

1. Project purpose and workflow diagram.
2. Capability overview that addresses researchers and AI-assisted personal knowledge-workflow users.
3. Five skills with one-sentence outcomes.
4. Quick start and initialization.
5. Optional automation and detailed operational documentation links.
6. Local-first privacy and safety boundaries.

## Non-goals

- No changes to scripts, runtime behavior, configuration, skills, or scheduling defaults.
- No new claims that the current Nature-platform collector supports all publishers.
- No machine paths, personal identifiers, credentials, or local runtime data in the public documentation.

## Validation

- Ensure English and Chinese documents describe the same product position and capability set.
- Check links and command paths locally.
- Search the staged public diff for local drive paths, user names, tokens, API keys, and private URLs before committing.
